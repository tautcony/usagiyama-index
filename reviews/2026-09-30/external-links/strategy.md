# 外部链接的抓取与展示规则

本次基于当前 `docs/` 的 255 个 Markdown 文件整理，不从原始数据反推链接。完整地址、标签、出现页面及行号在 [inventory.md](inventory.md)，机器可读结果在 [inventory.json](inventory.json)。本次只完成离线清点与方案，没有联网探测这些目标，也没有修改页面或启动批量抓取。下文是待实现的规则。

核心决定：**每条外链都登记；短链先解析；有保存价值的文章归档正文；视频、商品、百科、主页按资料链接展示。** 抓取成功后允许读本地副本，同时始终保留原地址和来源。

## 2. 发现、去重与目标识别

离线扫描 Markdown 链接（含引用式与自动链接）、裸 HTML 的 `a[href]`，以及可见纯文本 URL；代码块、图片资源、frontmatter 单列。纯文本 URL 也登记，不能因为当前不能点击就遗漏。扫描器使用 VitePress 的 Markdown 解析器，避免仅靠正则误认 Markdown 括号、参考定义和图片语法。

保存两种记录：

| 记录 | 最少字段 | 职责 |
| --- | --- | --- |
| 链接目标 | `id, requestedUrl, resolvedUrl, aliases, kind, policy, metadata, snapshot, lastAttempt` | URL 归一化、抓取结果和正文副本 |
| 引用位置 | `targetId, file, line/ordinal, originalUrl, label, form, role, fragment` | 保留每处原标签、语境、目标锚点和展示方式 |

实现时新增 `data/links.json` 导出清单；运行状态继续归现有 manifest/progress 管理，避免两份独立可修改的抓取事实源。`data/external.json` 继续保存已归档正文，不再把所有外链塞进它。当前审计 JSON 只用于清点，不是生产状态文件。

规范化顺序：

1. 相对 URL 以来源页面的原地址解析；只对精确的豆瓣 `link2` 主机/路径做有限次解包。仅接受 HTTP/HTTPS 进入网络队列，畸形地址留证据。
2. 小写 scheme/hostname、去默认端口；fragment 保留到引用记录，不参与网络请求。query 不整体删除：京阿尼的 `?p=1042` 是文章身份，`?author=18` 是作者列表，二者不能合并。
3. 只删除已明确识别的跟踪参数。HTTP/HTTPS、www、尾斜杠及短链等价关系，须由站点专用规则或实际重定向证明后再合并，禁止全站一刀切。
4. 先匹配原站 host + site ID + 对象类型 + ID，再匹配确实已生成的本地页面。其他小站、外站相似路径不能命中本站日记 ID。
5. 保留已存在的 `/external/topic-499780453`。新豆瓣日记可用 `/external/note-261864994`；其他文章用完整 URL 哈希派生的稳定 ID，避免不同站点的相同路径相撞。
6. 同一最终 URL 抓一次，所有短链及原 URL 成为别名；每个引用仍保留自己的标签。未知 fragment 保留在原地址，不虚构本地锚点。

## 3. 抓取队列如何生成

每轮先冻结清单，再分类和生成有限队列。正文抓取不递归跟随新外链；归档文章里发现的引用默认只做元信息登记，不因下一轮扫描了生成的 `/external/` 页面就继续扩张。目标记录保留 seed/发现深度和来源，列表分页只在对应豆列等适配器内处理。

| 优先级 | 候选范围 | 处理 |
| --- | --- | --- |
| P0 | 畸形 URL、334 个短链、直接可见的豆瓣日记 `261864994` | 核对异常；解析短链；补抓确定的日记；可回到本站的短链直接复用本地对象 |
| P1 | 房间公告中的考察/访谈/报告，以及文章开头标为“原文”的独立文章 | 归档正文，优先京阿尼员工博客、FC2、Hatena、Niconico 博客、新闻访谈；有现成译文时建立“原文 / 译文”关系 |
| P2 | 其他文章候选、社交帖子、豆列 | 文章通过提取校验后归档；帖子保存静态文本；豆列使用列表适配器 |
| P3 | 官网主页、百科、作品资料、商品、视频、音乐、个人主页 | 抓元信息；保留外链；不下载视频/音乐或遍历整站 |

优先级根据**引用语境和页面形态**决定，同一个域名可以同时有 P1 文章和 P3 导航。未知目标先列“待识别”，不可随便把页面正文全部当成文章保存。

短链解析成功后立刻重新分类：

- 最终指向已归档日记/照片/视频条目 → 本地路由；不再另建文章。
- 指向访谈或独立博客文章 → 进入正文队列。
- 指向商品/视频/主页 → 元信息队列。
- 解析失败 → 保留原短链与失败时间，显示“短链暂无法解析”；不声称目标已删除。

## 4. 请求、缓存与正文保存

**复用现有抓取、限速、缓存、进度和 Wayback 能力，按域名选择传输方式与解析器。** 豆瓣页面仍可用现有浏览器和登录态；普通外站先 HTTP，明确依赖 JS 且在范围内的文章再用浏览器。外站会话与豆瓣登录态隔离。

- 每域名默认串行、请求间隔 5–7 秒；先读取并缓存各目标 origin 的 robots 规则，较长的站点间隔优先。robots 缓存通常不超过 24 小时；规则不可达时暂缓新抓取。这是项目默认策略，`Crawl-delay` 作为站点扩展规则处理。[robots 标准](https://www.rfc-editor.org/rfc/rfc9309.html)
- 短链逐跳解析，最多 8 跳；每一跳重新检查目标、类型和网络地址，环路/本机私网地址停止。优先 HEAD 获取 Location；不支持 HEAD 或依赖页面跳转时，用有响应体上限的 GET；页面 meta refresh 需要明确解析，不任意执行跳转脚本。
- 默认单请求超时 30 秒，HTML 最大 5 MiB；429 遵从 `Retry-After`，临时网络错误/5xx 最多重试 2 次并退避，重复受限触发该域名熔断。403 标“访问受限”；识别到登录页才标“需要登录”；确认的 404/410 才标“源页面缺失”。
- 元信息保存最终 URL、标题、语言、作者、发布时间、摘要和可取得的封面。抓正文必须提取主内容并校验，不以 HTTP 200 作为“已归档”的充分条件；登录页、错误页、目录页、空正文和不支持的页面各有结果。
- 独立文章优先使用少数实际出现的站点适配器，通用提取器作为后备。正文清除脚本与在线嵌入；正文图片沿用媒体归档和本地路径，无本地图时保留说明和源图链接。
- 保存原始响应缓存、正文、内容 hash、解析器版本和采集时间。本文档中的文章/主页分类只是候选，最终以解析结果确认。

缓存规则作为同步逻辑实现，不依赖浏览者点击：

| 数据 | 默认重新检查条件 |
| --- | --- |
| 已成功解析的短链 | 30 天后或显式重查；失败时保留上一次的目标 |
| 未归档的元信息 | 30 天后 |
| 成功保存的历史文章 | 默认读缓存；显式 refresh 时重新验证；新候选照常抓取 |
| 429 / 超时 / 5xx | 到退避时间再重试 |
| 需要登录 / 403 / 404 / 410 / 解析失败 | 记录具体原因；显式重查，避免每次同步无休止请求 |

HTTP refresh 优先使用服务器已有的 ETag / Last-Modified 做条件请求，304 只更新检查时间，200 且正文变化再更新副本；浏览器传输若不支持此能力则正常获取并比对内容 hash。[HTTP 条件请求标准](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests)

源页面不可得且启用现有 `--archive` 时，文章候选可尝试 Wayback；记录目标地址、快照时间和快照来源。取到快照后同样验证正文，不把快照可用性 API 返回成功等同于正文完整。[Wayback API](https://archive.org/help/wayback_api.php)

**已有正文副本与本次请求结果分开记录。** 刷新失败不能清空旧正文或把已可阅读的本地页替换成“正文未能归档”；显示“已保存副本；最近检查受限/源页面失效”。内容保存状态与源页面当前可达状态不能共用一个覆盖字段。

## 5. 页面怎么展示

| 场景 | 主链接行为 | 补充信息 |
| --- | --- | --- |
| 原文中的文章引用，有本地正文 | 原标签链接到本地归档 | 邻近的“原文”入口/资料面板保留源地址 |
| 有确定本地对象的短链 | 指向对应日记或具体照片/视频锚点 | 资料详情显示原短链和解析后的地址 |
| 只有元信息的官网/资料/视频/商品 | 原标签仍链接到源站 | 需要时显示平台、类型和采集时间 |
| 尚未抓取 / 不支持正文提取 | 保留可点击的原地址 | 目录中标“仅外链”或“待归档”，不标“失效” |
| 原页面失效，但有副本 | 指向可阅读的本地正文 | “原页面失效，阅读保存副本” |
| Wayback 补足 | 指向本地副本 | 清楚显示历史快照日期及快照入口 |
| 没有副本且确认失效 / 受限 | 保留原标签和原地址 | 显示实际状态；快照入口仅在确定存在时提供 |
| URL 畸形 / 拼接可疑 | 保留原文字证据 | “地址待核对”，不生成自动抓取任务 |

正文内默认保持紧凑：保留原来的引用标签、语言、段落和顺序；不把每一个外链强制改成大卡片。详细元信息和状态放到文章末尾“引用资料”列表及独立链接目录，重要正文缺失才用提示块。

广播和相册说明中的纯文本 URL 需要一个统一的正文链接转换入口：只把确认完整的 URL 转可点击链接，并应用同样的本地改写规则。不能只改 Markdown 的 `linkify` 设置，因为广播 `<article>` 内的纯文本处于裸 HTML 中，仍不会被自动链接化。异常地址先保持原文字。

两个目录分工明确：

- `/external/` 继续只列归档正文；归档篇数只计算提取成功、可阅读的文章。已有 `topic-499780453` 的页尾“原站页面”保持外链，不把自己改写成自己的本地路由。
- 新 `/links/` 汇总外部资料，按文章、官方资料、百科、视频/音乐、社交、商品、待解析分组；提供域名/状态筛选、所有引用页面入口。源分组/房间信息用于关联，不替代原房间结构。

外链统一新窗口及 `rel="noopener noreferrer"`，本地链接同窗口。远程封面/社交 iframe 不在浏览时拉取，只有已下载的本地封面才能显示；无图的链接正常以文字呈现。

## 6. 实现顺序与验收

1. **登记与统一链接解析**：新增目标/引用记录，保留所有 occurrence；把链接改写规则集中在一个入口，覆盖 Markdown、广播 HTML、相册说明、房间页和目录。本次脚本可作为离线清点基线，后续生产发现应在生成前处理，避免“先生成再修改”的双写流程。
2. **短链和元信息**：独立队列、逐跳解析、去重、本地对象回链；dry-run 显示分类后的任务数量与预计请求数。不能直接把 842 当作 842 次请求，短链、robots、正文、图片各有额外请求。
3. **文章归档**：先补豆瓣日记，再接京阿尼员工博客、FC2、Hatena 等 P1 适配器；复用正文/媒体/Wayback 流程和旧路由；不把其他目标交给豆瓣文章解析器。
4. **展示与刷新**：实现 `/links/`、引用资料列表和状态；补充正文快照与最后检查分离、刷新缓存和仅更新受影响页面。

验收以当前 docs 清单为基线：

- 任一目标能查到原标签、所有引用位置；扫描过程不访问网络。URL 数变化能解释为源文变化、别名合并或修正。
- 同一文章的多个别名只抓取一次；京阿尼不同 `?p=` 不合并；`#` 不进入请求；不同主机相同路径不误命中本站对象。
- 短链可以转到既有日记/照片；失败保留可用的旧目标；抓文章不无限扩张目标集合。
- 豆列、商品、搜索结果和登录页不会因 HTTP 200 进入全文归档；403 不标作永久死亡；refresh 失败保留历史正文。
- 221 个纯文本目标也有明确处理结果，裸 HTML 广播内完整 URL 可以点击；3 个异常地址能回溯和核对。
- `emit` / offline 不联网；正文、封面和图片仅使用本地资源；生产构建通过已有死链检查；`BASE_PATH` 子路径下新增页面和锚点仍可用。

以上为制定的实施与验收规则，尚未表示生产逻辑已改好。
