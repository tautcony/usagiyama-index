# 外部链接的抓取与展示规则

初次清点基于当时 `docs/` 的 255 个 Markdown 文件，不从原始数据反推链接。完整地址、标签、出现页面及行号在 [inventory.md](inventory.md)，机器可读结果在 [inventory.json](inventory.json)。第 1 节的数量是该次历史基线，不能代表后来新增站外归档后的实时数量。

本次策略更新针对已经生成的豆瓣非小站页面：检查当前 `docs/external/`，结合本地缓存 HTML 与解析/生成代码定位格式问题，并在第 7 节规定每种类型的抓取、提取、展示和验收。没有重新联网抓取，也没有修改生产代码或生成页面。

核心决定：**每条外链都登记；短链先解析；页面按实际类型提取结构化内容，再用对应模板展示。** 文章保存正文，豆列保存有序条目，豆瓣作品/人物保存资料快照，照片保存图片与说明，预告片保存视频信息。商品、百科、一般主页按资料链接展示。HTTP 成功、提取成功、内容完整分别判断，不能统一当成“文章已归档”。

## 2. 发现、去重与目标识别

离线扫描 Markdown 链接（含引用式与自动链接）、裸 HTML 的 `a[href]`，以及可见纯文本 URL；代码块、图片资源、frontmatter 单列。纯文本 URL 也登记，不能因为当前不能点击就遗漏。扫描器使用 VitePress 的 Markdown 解析器，避免仅靠正则误认 Markdown 括号、参考定义和图片语法。

保存两种记录：

| 记录 | 最少字段 | 职责 |
| --- | --- | --- |
| 链接目标 | `id, requestedUrl, resolvedUrl, aliases, kind, policy, metadata, snapshot, lastAttempt` | URL 归一化、抓取结果和正文副本 |
| 引用位置 | `targetId, file, line/ordinal, originalUrl, label, form, role, fragment` | 保留每处原标签、语境、目标锚点和展示方式 |

实现时新增 `data/links.json` 导出清单；运行状态继续归现有 manifest/progress 管理，避免两份独立可修改的抓取事实源。`data/external.json` 保存按类型解析的站外归档对象，包括正文、列表和资料快照；未请求/仅登记的外链留在链接清单中。当前审计 JSON 只用于清点，不是生产状态文件。

规范化顺序：

1. 相对 URL 以来源页面的原地址解析；只对精确的豆瓣 `link2` 主机/路径做有限次解包。仅接受 HTTP/HTTPS 进入网络队列，畸形地址留证据。
2. 小写 scheme/hostname、去默认端口；fragment 保留到引用记录，不参与网络请求。query 不整体删除：京阿尼的 `?p=1042` 是文章身份，`?author=18` 是作者列表，二者不能合并。
3. 只删除已明确识别的跟踪参数。HTTP/HTTPS、www、尾斜杠及短链等价关系，须由站点专用规则或实际重定向证明后再合并，禁止全站一刀切。
4. 先匹配原站 host + site ID + 对象类型 + ID，再匹配确实已生成的本地页面。其他小站、外站相似路径不能命中本站日记 ID。
5. 保留已存在的 `/external/topic-499780453`。新豆瓣日记可用 `/external/note-261864994`；其他文章用完整 URL 哈希派生的稳定 ID，避免不同站点的相同路径相撞。
6. 同一最终 URL 抓一次，所有短链及原 URL 成为别名；每个引用仍保留自己的标签。未知 fragment 保留在原地址，不虚构本地锚点。

## 3. 抓取队列如何生成

每轮先冻结清单，再分类和生成有限队列。正文抓取不递归跟随新外链；归档文章里发现的引用默认只做元信息登记，不因下一轮扫描了生成的 `/external/` 页面就继续扩张。目标记录保留 seed/发现深度和来源，列表分页只在对应豆列等适配器内处理。

| 优先级 | 候选范围 | 处理 |
| --- | --- | --- |
| P0 | 现有豆瓣站外页面的误解析、畸形 URL、334 个短链 | 先从缓存修复现有类型及成功状态，再核对异常、解析短链；可回到本站的短链复用本地对象 |
| P1 | 房间公告中的考察/访谈/报告，以及文章开头标为“原文”的独立文章 | 归档正文，优先京阿尼员工博客、FC2、Hatena、Niconico 博客、新闻访谈；有现成译文时建立“原文 / 译文”关系 |
| P2 | 其他文章候选、社交帖子、豆列、豆瓣作品与人物资料 | 文章通过提取校验后归档；帖子保存静态文本；豆列/资料页使用类型适配器 |
| P3 | 官网主页、百科、商品、视频、音乐播放页、个人主页 | 抓元信息；保留外链；不下载视频/音乐或遍历整站；音乐专辑资料与音乐播放页分开 |

优先级根据**引用语境和页面形态**决定，同一个域名可以同时有 P1 文章和 P3 导航。未知目标先列“待识别”，不可随便把页面正文全部当成文章保存。

短链解析成功后立刻重新分类：

- 最终指向已归档日记/照片/视频条目 → 本地路由；不再另建文章。
- 指向访谈或独立博客文章 → 进入正文队列。
- 指向商品/视频/主页 → 元信息队列。
- 解析失败 → 保留原短链与失败时间，显示“短链暂无法解析”；不声称目标已删除。

## 4. 请求、缓存与正文保存

**复用现有抓取、限速、缓存、进度和 Wayback 能力，按域名选择传输方式与解析器。** 豆瓣页面仍可用现有浏览器和登录态；普通外站先 HTTP，明确依赖 JS 且在范围内的文章再用浏览器。外站会话与豆瓣登录态隔离。

- 每域名默认串行、请求间隔 5–7 秒；先读取并缓存各目标 origin 的 robots 规则，较长的站点间隔优先。robots 缓存通常不超过 24 小时；规则不可达时暂缓新抓取。这是项目默认策略，`Crawl-delay` 作为站点扩展规则处理。[robots 标准](https://www.rfc-editor.org/rfc/rfc9309.html)
- 短链逐跳解析，最多 8 跳；每一跳重新检查目标、类型和网络地址，环路/本机私网地址停止。优先 HEAD 获取 Location；不支持 HEAD 或依赖页面跳转时，用有响应体上限的 GET；页面 meta refresh 需要明确解析，不任意执行跳转脚本。
- 默认单请求超时 30 秒，HTML 最大 5 MiB；429 遵从 `Retry-After`，临时网络错误/5xx 最多重试 2 次并退避，重复受限触发该域名熔断。403 标“访问受限”；识别到登录页才标“需要登录”；确认的 404/410 才标“源页面缺失”。
- 元信息保存最终 URL、标题、语言、作者、发布时间、摘要和可取得的封面。抓正文必须提取主内容并校验，不以 HTTP 200 作为“已归档”的充分条件；登录页、错误页、目录页、空正文和不支持的页面各有结果。
- 独立文章优先使用少数实际出现的站点适配器，通用提取器作为后备。正文清除脚本与在线嵌入；正文图片沿用媒体归档和本地路径，无本地图时保留说明和源图链接。
- 保存原始响应缓存、正文、内容 hash、解析器版本和采集时间。本文档中的文章/主页分类只是候选，最终以解析结果确认。

缓存规则作为同步逻辑实现，不依赖浏览者点击：

| 数据 | 默认重新检查条件 |
| --- | --- |
| 已成功解析的短链 | 30 天后或显式重查；失败时保留上一次的目标 |
| 未归档的元信息 | 30 天后 |
| 成功保存的历史文章 | 默认读缓存；显式 refresh 时重新验证；新候选照常抓取 |
| 429 / 超时 / 5xx | 到退避时间再重试 |
| 需要登录 / 403 / 404 / 410 / 解析失败 | 记录具体原因；显式重查，避免每次同步无休止请求 |

HTTP refresh 优先使用服务器已有的 ETag / Last-Modified 做条件请求，304 只更新检查时间，200 且正文变化再更新副本；浏览器传输若不支持此能力则正常获取并比对内容 hash。[HTTP 条件请求标准](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests)

源页面不可得且启用现有 `--archive` 时，文章候选可尝试 Wayback；记录目标地址、快照时间和快照来源。取到快照后同样验证正文，不把快照可用性 API 返回成功等同于正文完整。[Wayback API](https://archive.org/help/wayback_api.php)

**已有正文副本与本次请求结果分开记录。** 刷新失败不能清空旧正文或把已可阅读的本地页替换成“正文未能归档”；显示“已保存副本；最近检查受限/源页面失效”。内容保存状态与源页面当前可达状态不能共用一个覆盖字段。

## 5. 页面怎么展示

| 场景 | 主链接行为 | 补充信息 |
| --- | --- | --- |
| 原文中的文章引用，有本地正文 | 原标签链接到本地归档 | 邻近的“原文”入口/资料面板保留源地址 |
| 有确定本地对象的短链 | 指向对应日记或具体照片/视频锚点 | 资料详情显示原短链和解析后的地址 |
| 只有元信息的官网/资料/视频/商品 | 原标签仍链接到源站 | 需要时显示平台、类型和采集时间 |
| 尚未抓取 / 不支持正文提取 | 保留可点击的原地址 | 目录中标“仅外链”或“待归档”，不标“失效” |
| 原页面失效，但有副本 | 指向可阅读的本地正文 | “原页面失效，阅读保存副本” |
| Wayback 补足 | 指向本地副本 | 清楚显示历史快照日期及快照入口 |
| 没有副本且确认失效 / 受限 | 保留原标签和原地址 | 显示实际状态；快照入口仅在确定存在时提供 |
| URL 畸形 / 拼接可疑 | 保留原文字证据 | “地址待核对”，不生成自动抓取任务 |

正文内默认保持紧凑：保留原来的引用标签、语言、段落和顺序；不把每一个外链强制改成大卡片。详细元信息和状态放到文章末尾“引用资料”列表及独立链接目录，重要正文缺失才用提示块。

广播和相册说明中的纯文本 URL 需要一个统一的正文链接转换入口：只把确认完整的 URL 转可点击链接，并应用同样的本地改写规则。不能只改 Markdown 的 `linkify` 设置，因为广播 `<article>` 内的纯文本处于裸 HTML 中，仍不会被自动链接化。异常地址先保持原文字。

两个目录分工明确（本次更新调整了原先“`/external/` 只列文章”的方案）：

- `/external/` 呈现已经保存或尝试归档的站外对象，标题改为“站外归档”，按文章、豆列、电影/剧集、音乐专辑、人物、照片、预告片、未完整归档分组。文章数、资料数、列表数分别统计；失败占位不算成功归档。保留现有详情 URL，具体见第 7 节。已有 `topic-499780453` 的页尾“原站页面”保持外链，不把自己改写成自己的本地路由。
- 新 `/links/` 汇总外部资料，按文章、官方资料、百科、视频/音乐、社交、商品、待解析分组；提供域名/状态筛选、所有引用页面入口。源分组/房间信息用于关联，不替代原房间结构。

外链统一新窗口及 `rel="noopener noreferrer"`，本地链接同窗口。远程封面/社交 iframe 不在浏览时拉取，只有已下载的本地封面才能显示；无图的链接正常以文字呈现。

## 6. 实现顺序与验收

1. **修复现有豆瓣内容**：先完成第 7 节的类型分派、状态判定和专用模板，从已有缓存重解析。日记/话题、豆列、电影/音乐、人物、照片/预告片依次验证；搜索、用户主页、跳转页单独处理。
2. **登记与统一链接解析**：新增目标/引用记录，保留所有 occurrence；集中链接改写规则，覆盖 Markdown、广播 HTML、相册说明、房间页和目录。生产发现放在生成前，避免“先生成再修改”的双写流程。
3. **补齐缺失内容**：缓存缺少的图片、列表后续页、已识别的动态评论/人物模块，生成明确的补抓队列；其他短链与元信息使用独立队列。dry-run 显示分类后的任务数量与预计请求数，不能直接把 842 当作 842 次请求。
4. **扩展其他外站与刷新**：接京阿尼员工博客、FC2、Hatena 等 P1 适配器；实现 `/links/` 和引用资料列表；完善快照与最后检查分离及增量刷新。

通用链接验收以初次 docs 清单为历史基线；本轮新增豆瓣内容按第 7 节逐类型验收：

- 任一目标能查到原标签、所有引用位置；扫描过程不访问网络。URL 数变化能解释为源文变化、别名合并或修正。
- 同一文章的多个别名只抓取一次；京阿尼不同 `?p=` 不合并；`#` 不进入请求；不同主机相同路径不误命中本站对象。
- 短链可以转到既有日记/照片；失败保留可用的旧目标；抓文章不无限扩张目标集合。
- 豆列、作品资料、商品、搜索结果和登录页不会因 HTTP 200 进入文章归档；列表/资料须通过对应类型校验；403 不标作永久死亡；refresh 失败保留历史内容。
- 221 个纯文本目标也有明确处理结果，裸 HTML 广播内完整 URL 可以点击；3 个异常地址能回溯和核对。
- `emit` / offline 不联网；正文、封面和图片仅使用本地资源；生产构建通过已有死链检查；`BASE_PATH` 子路径下新增页面和锚点仍可用。

以上为制定的实施与验收规则，尚未表示生产逻辑已改好。

### 7.2 类型识别与模型契约

先解包、解析重定向，再用**最终 hostname + 完整路径 + 页面特征**确认类型；请求 URL 和最终 URL 都保存。OG/JSON-LD 可补字段和佐证，不能单独覆盖相矛盾的页面内容。现有缓存没有保存 `final_url`，即使传输层拿到了也没有写入响应缓存：后续须补这个字段；旧缓存可用 `og:url` 等佐证建立明确别名，证据不足时不要假定发生了重定向。

| 类型 | URL 识别范围 | 专用载荷 |
| --- | --- | --- |
| `douban_note` | 主站 `/note/{id}` | 文章标题、作者/链接、发布/修改时间、正文块、图片、评论与完整度 |
| `douban_topic` | 主站 `/topic/{id}` | 同上；另保留话题关联信息，仅在源页提供时填写 |
| `douban_doulist` | 主站 `/doulist/{id}` | 标题、编者、简介、有序条目、分页信息、完整度 |
| `douban_movie` | `movie.douban.com/subject/{id}` | 电影/剧集属性、简介、海报、评分快照、相关人物/作品引用 |
| `douban_music` | `music.douban.com/subject/{id}` | 专辑属性、简介、封面、曲目、评分快照 |
| `douban_book` | `book.douban.com/subject/{id}` | 书籍属性、简介、目录、封面；当前样本未出现，未验证前标不支持 |
| `douban_person` | 旧 `movie.douban.com/celebrity/{id}` 与主站 `/personage/{id}` | 姓名、属性、头像、简介、已取得的作品/获奖条目、模块完整度 |
| `douban_photo` | 已确认的 `/photos/photo/{id}`，以及主站照片详情路径 | 照片 ID、图片地址/本地文件、说明、上传者、关联作品、前后图片引用 |
| `douban_trailer` | `movie.douban.com/trailer/{id}` | 标题、关联作品、预告片名称、时长、发布日期、封面、稳定播放页面 |
| `douban_search` | `/subject_search` 等已确认搜索路径 | 查询参数、结果预览、检查时间；不属于文章 |
| `douban_profile` | 主站 `/people/{name-or-id}` | 昵称、源地址、可见的公开简介和头像；不抓关注/友邻/活动流 |
| 跳转 / 操作 / 未知类型 | `link2`、登录、编辑、收藏、举报、分享等 | 跳转解析真实目标；操作路径不入归档队列；未知类型保留链接与“不支持”原因 |

实现使用一个分派入口加少量类型解析函数，仍复用现有传输、媒体和 Markdown 工具。统一外层保存 `kind, sourceUrl, finalUrl, aliases, title, origins, payload, media, fetchStatus, parseStatus, completeness, parserRevision`；`payload` 采用普通 dataclass/JSON，不建立通用 DOM 映射框架。

`origins` 保存所有入链的来源页面与引用标签，不能只保留第一个字符串；它用于页面的“引用自”，不是对象所属的“原站索引分组”。标题回退为源引用标签，再回退对象 ID；不能生成 `[](/external/...)`。

复用第 2 节的 URL 身份规则，并补以下约束：

- 电影、音乐、书籍的相同 subject ID 不是同一对象，内部实体键包含 host/type。现有 `/external/subject-{id}` 作为既有别名保留；新对象采用含类型的 ID，发生冲突时不覆盖。
- 人物旧 celebrity ID 与新 personage ID 只有在实际跳转/`og:url` 等证据确认后建立别名；既有 `/external/celebrity-1054399` 保留可读入口。
- 照片身份取完整 `2198139096`，新规范页可用 `/external/photo-2198139096`；`/external/photos-photo` 保留别名，不能让所有照片都落在这个 ID。
- 搜索身份包含 `search_text`、`cat` 等有意义参数；分页 URL 归所属集合的采集页，不能与集合首屏混成一个缓存键。
- `link2` 不再是独立内容。该例映射到已存在的 `/notes/348784334`；已生成的 `/external/link2` 只作为明确指向该对象的兼容入口。先重写入链，再处理旧页面，不突然删除仍被引用的路由。

### 7.3 日记与话题：完整文章模板

**日记**：已确认样本的 `.note-header` 提供标题、作者和日期；正文选 `#link-report > .note`，不把父容器中的 `#link-report_note` 举报入口收入正文。适配器需识别新旧日记布局、短版/完整版，只采用一份完整正文，避免两份重复。正文之外的标签、喜欢数、分享、推荐、评论入口不混入文章。

**话题**：当前 `topic-499780453` 使用 `.topic-content` 和 `.topic-meta`，与日记 `#link-report` 布局不同；分别读取标题、正文、作者及发布时间/修改标识。来源只有“已编辑”时保留标识，不虚构修改时间；“上海”等定位信息不解析成作者或日期。

正文保存段落、标题、列表、引用、链接、图注与图片顺序。空行、`br` 和段落按实际语义转换，不把每行都升成标题；问答按原顺序展示，可将已有问题段落加粗，但不把所有以破折号开头的句子自动视为问题。正文图使用 `src/data-src/data-original`，按最终页面 URL 解析后归档；转换时传入 `image_map`，不能靠 `keep_remote_images=False` 直接抹掉未保存的图片。只包图片的布局表格可展开，真实数据表保留表头/单元格，改变当前无条件拆掉全部表格的规则。

模板：页面标题 → 作者/日期/来源 → 正文 → 图片缺失说明（如有）→ 真实评论及完整度 → 所有引用页面 → 原站入口。原文中的引注、外文和译者说明保留，不重写内容措辞。主标题只渲染一次，正文小标题按层级输出。

成功条件：对象 ID 匹配、正文容器符合该类型且存在真实文本/内容媒体，作者/日期缺失须说明但不伪造。HTTP 200 的错误页、举报入口或占位骨架不算成功。正文成功、评论未完成可显示“正文已保存；评论未完整归档”，不丢正文。

### 7.4 豆列：有序集合模板

不能使用 `#link-report`；当前缓存中它只有“投诉”。按豆列信息区提取标题、编者、简介，再枚举 `.doulist-item`。当前 `43094984` 的主条目标题可在 `.doulist-subject > .title a` 定位；不要用 `.doulist-item .title` 的第一个节点，因为嵌入的视频区也有“播放全片”等标题。

每个条目保存豆列 item ID、源页位置、目标 URL/类型、标题、条目摘要、编者推荐说明、可取得的封面、加入时间（源页有时才填）。其他豆列可能容纳日记、人物、照片等；以条目实际结构分派，不能只支持电影。推荐说明属于编者内容，和被推荐作品的简介、条目评论分开。

分页按源页明确的下一页或范围获取，保留源默认排序与 `sort` 参数；不同豆列允许包含同一目标。实体去重不消除编者重复编排的条目。分页重复项按 item ID 去重，跨页不能仅按作品 URL 去重。记录声明数量、枚举条目数、已抓页和缺页，首页完成不是全集完成；请求限额或某页失败时展示“已保存 X 项，列表未完整”。

模板：标题/编者/简介 → 完整度与排序说明 → 有序条目（标题、简要属性、推荐理由，可选本地封面）→ 源豆列。少量条目可用序号列表，大集合按固定页大小展示；不用投诉、收藏、分享按钮充当内容。不自动抓豆列中所有条目的详情，详情补抓仍受队列范围限制。

成功条件：正确豆列 ID 和可验证的条目列表；源页明确空豆列可显示“空豆列”，仅缺少条目容器不能认定为空。豆列条目页的评论默认不抓；确需保存时必须归到对应 item，不能当成整个豆列的全局评论。

### 7.5 电影/剧集、音乐专辑、书籍：资料模板

**电影/剧集**：从 `h1/OG` 取名称，从 `#mainpic` 取海报，从 `#info` 按标签取导演、编剧、演员、类型、国家/地区、语言、上映时间、片长/集数、别名和 IMDb。不要依赖换行后固定第几项。剧情简介按已确认的简介模块（样本 `.related-info` 内的 `#link-report-intra`）读取，优先完整内容，避免短版/隐藏长版重复。人物名字与 URL 成对保留，字段显示紧凑表格/列表。

评分仅保存页面上可取得的值、评价人数和 `checkedAt`，文案明确“采集时评分”；不按快照评分给站内文章排序。演职员、获奖等可作独立的有限资料模块；默认不保存推荐电影、短评列表、影评列表、讨论区、购票和收藏操作。原站直接引用某篇影评时，将它作为独立文章候选，不能通过电影详情页附带的影评推荐递归扩大范围。

**音乐专辑**：单独读取 `#info` 的表演者、专辑类型、介质、发行日期、出版者、唱片数、条形码；保存 `#mainpic` 封面、简介、评分快照和 `.track-list .track-items` 曲目，保持曲目序号、多盘分组及源页提供的时长。不能仅取 `#link-report` 简介而漏掉资料和曲目，也不抓“想听/在听”、推荐专辑、播放操作和乐评列表。模板为专辑资料 → 简介 → 有序曲目 → 来源。

**书籍**：预留独立类型，字段为作者/译者、出版社、出版日期、页数、定价快照、装帧、ISBN、简介、源页提供的作者介绍/目录及封面。当前没有缓存样本，选择器和完整度暂未验证；只有补充实际样本和测试后才启用，不能宣称电影解析器已支持书籍。

成功条件：对应 host 与 subject ID、有效标题，以及至少一组类型特有属性/简介；只有导航/操作文字不算资料快照。核心资料可保存，缺封面、缺简介/曲目等按模块标缺失，不生成空小节。资料页不调用通用文章评论解析器，未抓评论无需显示“0 条评论”。

### 7.6 人物：资料与模块模板

旧 `celebrity` 和新 `personage` 视作两种源布局，输出一种人物资料模型。当前样本已确认 `.subject-target h1`、`.subject-property`、`.subject-intro .content` 和 `.subject-awards`；分别取姓名、属性、简介与当前页展示的获奖项，并从头像容器取本地图。

属性以“字段—值”呈现，保留姓名、职业、出生日期/地点、别名、家庭成员、IMDb 等源信息；不把值拆成隔着空行的列表段落。简介保留段落，展开前后两份内容只能留一份；“展开”不是正文。获奖项保存年份、奖项、获奖/提名及作品引用。

作品区要区分页面已显示的数据与 `.subject-skeleton`：缓存只有骨架时不能显示“最近 5 部作品”空标题。浏览器等待对应模块出现真实条目或明确空状态，采用有上限的模块就绪等待；仍未取到则标“作品列表未加载”，人物核心资料依然可读。当前页仅预览 5 部作品/3 项获奖时明确标“页面预览”，不声称完整作品或完整获奖档案；不默认遍历“全部作品/全部照片”。

模板：姓名/头像 → 属性表 → 人物简介 → 已取得的作品与获奖模块（各自完整度）→ 引用自/来源。编辑、关注、推荐、分享、添加豆列操作不渲染。

成功条件：识别出人物 ID/别名、姓名与人物特有属性或简介；模块待加载只能影响相应模块完整度，不能生成虚假的空列表或抹去人物资料。

### 7.7 照片与预告片：媒体模板

**照片**：以照片 ID 定位图片，当前样本 `.photo-show img` 是核心显示图，`.photo_descri` 提供说明（允许真实为空）。优先页面给出的原图/大图，按现有媒体逻辑下载、校验后写本地路径；不能把另一张推荐图或“上一张”缩略图当成主图。不自行替换 CDN URL 猜出未验证的原图。源站提供的“查看大图”原地址保留为来源，页面展示本地图、说明、上传者和所属作品。

前后照片是引用，不是需要跟随遍历相册的任务。已归档的前后照片可链接本地，否则解析成绝对源地址。下载失败时以明确的“图片尚未保存”及源图入口呈现，不只剩导航/回应表单。

照片成功需要核心图片已下载并通过格式校验；只有页面标题/元信息时标“照片资料已保存，图片缺失”，不能算照片归档成功。模板是图片 → 图注/署名/作品 → 可选前后导航 → 原站。

**预告片**：当前样本的 `.main-info`、当前视频信息与关联作品链接是元信息来源，封面从可信的 poster/OG/当前视频容器提取。保存标题、片名、预告名称、时长、发布日期和稳定的 `/trailer/{id}` 页面链接。排除播放器 Loaded/Progress/Mute/Fullscreen、推荐预告片、报错/分享和空回应表单。

原缓存的 MP4 URL 含带时间的签名路径，可能过期；可保留在原始响应证据中，但不作为用户的稳定播放链接。默认不下载视频，不嵌入远程播放器。模板是本地封面（可用时）→ 视频资料 → “在豆瓣播放” → 关联作品/来源。成功表示视频资料提取成功；状态文案明确“预告片资料已保存，视频未归档”，不能与视频文件本地保存混为一谈。

### 7.8 搜索、用户主页、跳转及未支持页面

**搜索**：保存原查询、分类及源搜索链接。当前 `subject-search` 缓存只有动态根容器，没有文章正文；可把有限的搜索结果作为附加预览，但须等待真实结果/明确无结果状态，按顺序保存标题、年份、类型、目标 URL。只保存首页预览时标明范围。不自动抓取全部搜索结果，不把根容器空白解释为“0 条结果”。默认在资料目录显示搜索入口；若保留现有详情 URL，使用“搜索资料”模板，没有“正文未能归档”的文章提示。

**用户主页**：当前 `people-phil` 为 404，占位使用来源标签“phil”与真实状态；不生成空标题。可取得的公开主页只保存昵称、简介、头像及原链接，按个人资料模板展示，不抓其日记/友邻/活动流。HTTP 404 不推断注销原因，不自动把“用户主页不可得”文案写成“文章正文缺失”。

**跳转**：`link2` 与短链先解析真实目标再进入类型分派；包裹的小站文章复用现有日记，包裹的真正外站文章交对应外站适配器。缺目标、环路、畸形地址保存诊断，不创建名为 link2 的文章。

**其他豆瓣页面**：主站文章评论、影评/乐评/书评、群组讨论、照片集合等，只有明确 URL 规则、缓存样本与专用解析器时才启用；可复用文章/列表模板，但不能拿 `.article` 主栏作通用兜底。登录、验证码、编辑、上传、举报、关注、评分、收藏、分享路径不作内容候选。不支持页面保留原链接和原因，可先保存已确认的元信息。

### 7.9 评论、链接、图片和成功状态的共用约束

评论只在类型专属的评论容器内读取。适配器分别识别旧静态评论、新版主站评论、集合 item 评论；作者、日期、comment ID、正文、引用回复与所属对象成组保存。排除 `.skeleton`、pending/loading、form、模板和空节点；作者未标明但正文真实存在可显示“作者未标明”，不能为每个骨架造“匿名 /（空）”。只有媒体的真实评论也要按实际媒体内容判断，不以纯文字为空直接删除。

等待策略以必要模块为目标，不能只等 `domcontentloaded` 就声称动态评论/作品完整；也不无限等待网络空闲。限定等待时间后记录 partial/pending。真实评论分页依据该类型自己的参数与条目 ID；只抓到首屏时显示“已保存 X 条，评论未完整”，评论声明总数与保存数分别记录。正文成功不要求所有评论都成功，但评论抓取结果不能冒充完整。电影/音乐资料页默认没有评论任务，豆列默认没有集合全局评论。

所有图片从源 DOM 映射到统一媒体记录，再传入每种模板/Markdown 上下文；正文图、海报、人物头像、专辑封面、照片主图和预告封面分别记录角色。媒体缺失不静默删掉有意义的正文，也不显示远程裂图。

处理相对/协议相对 URL 时先 `urljoin(effectiveBaseUrl, href/src)` 再做本地实体匹配。基址来自真实最终响应 URL，并按有效的源文档 `<base href>` 处理；OG URL 只作身份佐证，不能直接代替浏览器实际基址，尤其要注意尾斜杠。旧缓存缺最终地址时用类型明确的源路径规则修复，不能任意补斜杠。例如人物页的 `photos` 应解析为该源人物页面下的地址，电影页 `/subject/1291835/celebrities` 应是豆瓣绝对链接，不能变成本站不存在的路径。已知本地对象可改写，未支持的源页面保留绝对外链；操作链接从该类型的提取区删除。查询和锚点按第 2 节规则处理，页尾“原站”始终为源地址。

采用三个独立判定，统一导出用户可理解的状态文案：

| 判定 | 保存内容 | 影响 |
| --- | --- | --- |
| `fetchStatus` | 状态码、最终 URL、检查时间、受限/网络错误 | 说明此次源请求结果，不能覆盖历史副本 |
| `parseStatus` | `ok/failed/unsupported`、kind、原因、parserRevision | 类型核心字段通过校验才成功；空内容和错误模块不 `mark_done` 为成功 |
| `completeness` | 正文/条目/评论/作品/媒体各模块的 `complete/partial/unknown/not_requested` 及计数 | 明确已保存范围；没有开启的任务不冒充缺失或“0 条” |

还需保留第 4 节的“已保存副本”与“最后尝试”边界。解析失败不自动发起网络重试风暴：进度记录解析失败和版本，版本变更或显式重查时再解析/请求。已有 `ok` 但误抓“投诉”的对象不能因 done 而跳过修复；新版解析器必须使相应类型旧记录失效。

### 7.10 目录文案、修复步骤与逐类型验收

`/external/` 建议使用标题“站外归档”，简介替换为：

> 这里保存了原站公告、正文、评论和广播所引用的站外内容，包括文章、豆列、作品与人物资料，以及照片和预告片信息。页面按类型整理；内容不完整或暂时不可获取时会单独标明，原地址始终保留。

这段为待实现的页面文案。取消“一部分索引链接需要登录、登录后已一并归档”的泛化说明：来源已经不只是索引，资料页与文章也不具有相同的登录/提取条件。页面仍在原 URL 下，现有导航可保留；目录按 `kind` 分组，未识别、提取失败、源页不可得单列。来源显示“引用自：About PPK / 日记标题 / 相册说明”等可点击本地入口，而不是对每个对象写“原站索引分组：日记编号”。

修复按以下顺序落地，先用现成缓存完成可验证的改动，再进行缺口补抓：

1. 冻结当前 82 个对象、原路由、原缓存和入链；新增类型分派和解析状态，修掉 `external.status = page.status` 抹掉解析失败的问题，冻结候选避免污染内容的出链继续扩张。
2. 日记/话题提取标题作者日期和干净正文；豆列重建有序条目；电影/音乐重建属性简介与曲目；人物重建资料、简介及已取得的模块；照片/预告片改用媒体模板。
